## 4. 相对SegFormer基础，本轮到底做了哪些设计改造

### 4.1 model.py：保留库内MiT编码器，自写轻量解码器

代码：`src/uavseg/model.py`。

1. 编码器仍直接调用Transformers的SegformerModel.from_pretrained，没有从零实现Transformer blocks，也没有自己做ImageNet预训练。
2. 四尺度特征分别经过1×1卷积、GroupNorm、GELU，统一为192通道，上采样至第一阶段的1/4分辨率后拼接融合。
3. 使用3×3深度卷积再1×1逐点卷积进行局部细化，新增参数较少；用于补充局部空间处理，而非替换编码器注意力。
4. 第一阶段高分辨率特征接边界头输出1通道boundary_logits。
5. 融合特征经细化后乘以 `1 + sigmoid(boundary_logits)`，再经Dropout2d(0.1)和1×1分类器输出9通道logits。
6. 门控值介于1与2之间，仅放大空间位置，不是抑制背景的0/1硬掩码；每个空间位置的门控对所有通道共享。边界预测错误也可能放大错误特征。

训练640输入时，第一阶段输出约160×160；整图1024推理时约256×256；loss/推理中再上采样回标签尺寸。边界分支位于同一模型内，最终只输出一张类别图，不是模型集成。其贡献需要和无边界分支/门控的同预算对照验证。

### 4.2 losses.py：像素、区域、边界三种监督

代码：`src/uavseg/losses.py`。

- Weighted CE：按像素类别权重计算交叉熵，忽略真实标签0，label smoothing=0.05。类别权重用于改变训练惩罚，不改变最终mIoU的等权类别平均规则。
- Soft Dice：softmax概率与one-hot真值计算区域重叠；忽略ID0，且只平均当前batch真值中出现的类别。减轻类别不平衡是设计目标，不是本轮已验证的因果结论。
- Boundary target：检测水平/垂直相邻的不同有效类别，两侧标边界，再通过3×3 max-pool扩展边界带。不会把Ignore与有效类的直接差异当作边界来源；最终valid mask排除Ignore像素。
- Balanced BCE：边界正类权重为负/正像素数比，裁剪到[1,20]，用于缓解边界像素少的问题。
- 总损失为CE + 0.3Dice + 0.1Boundary；训练、验证都计算该组合，但best模型根据mIoU而不是最低loss选取。

注意：将boundary_weight改0只取消边界辅助loss，门控仍参与前向和接收分割loss梯度。完整移除边界模块需要单独的结构实验。

### 4.3 data.py：尺度、方向、外观和稀有类别裁剪

代码：`src/uavseg/data.py`。

- 通过相对路径配对图像/标签，固定split按唯一文件stem取样，检查丢失、重叠和未使用样本。
- 图像双线性缩放，mask最近邻缩放，防止类别ID被插值成小数。
- 随机尺度0.75–1.5后裁剪640×640；水平/垂直翻转各50%，随机0/90/180/270度旋转，图像与mask同步。
- 亮度、对比度、色彩三个变换随机顺序，各自系数0.8–1.2；15%概率高斯模糊半径0.1–1.2。目的是覆盖拍摄条件变化，但不能保证覆盖实际测试域。
- 以50%概率对当前图尝试最多8个crop，只要ID5/7/8合计达到0.5%就接受；不是每个稀有类都达到0.5%，也不是50%的训练样本必含稀有类。
- 如果8次未达标，保留最后一次crop；如果原图根本没有裸地，重试裁剪无法创造裸地样本。当前没有按图像类别分布做过采样。
- 归一化使用ImageNet mean=[0.485,0.456,0.406]、std=[0.229,0.224,0.225]，与预训练输入保持一致。
- 验证training=false时不走缩放/裁剪/随机增强，保留整张原图；crop_size参数此时不意味着真的裁剪。

### 4.4 profile_dataset.py：用数据统计控制实验可比性

代码：`tools/profile_dataset.py`。

统计标签和外观，生成类别权重，并在512个候选中挑固定划分，减少随机划分造成的类别极端缺失。局限是类别权重用了全体标签，以及外观分布匹配不能替代场景独立性。该工具不是训练程序，不产生模型权重。

### 4.5 train.py：训练工程与优化策略

代码：`scripts/train.py`。

组织数据、模型、组合loss、分组AdamW、AMP、梯度累积/裁剪、warmup+poly、逐轮全图验证和检查点。随机种子与cuDNN确定性配置提升可重复性，但不是跨平台逐bit复现保证。验证batch固定为1，改变训练batch不会自动加速验证。

这些是训练策略/工程能力，不宜都包装成新算法。训练batch4×累积1与batch1×累积4的样本数相同，但batch聚合的Dice及边界正负比例权重可能不同，因此不能宣称两者数学上完全等价。

### 4.6 metrics.py、predict.py、make_submission.py：评估与交付

- `src/uavseg/metrics.py`：累计真值行、预测列的混淆矩阵，排除真实Ignore像素，计算全验证集逐类IoU；在真实有效类别上预测为0仍会形成该类别的漏检，不会被免费忽略。
- `scripts/predict.py`：从检查点重建完整网络，RGB+ImageNet归一化，整图单次前向，双线性还原logits再argmax，保存uint8 L图，无TTA或平均。
- `tools/make_submission.py`：校验文件名、数量、尺寸、模式、类别范围，再生成扁平ZIP。格式正确不代表mIoU高，但能排除提交格式失误。
- `tools/check_dataset.py` / `tools/prepare_dataset.py`：分别负责数据体检/安全解压，不改变模型结构；本轮服务器实际选择了手工unzip整理，不应记录成自动解压脚本执行结果。

## 5. 对第一轮结果的分析

### 5.1 哪些结论已被结果支持

完整训练由57.48%验证mIoU提升到79.95%，说明组合方案能有效学习，且没有明显的训练失败。后期已有较高平台，验证端没有持续崩溃；这并不证明测试域泛化充分。

验证弱项是Barren 60.8849%和Background 72.5771%；Vehicle 80.7155%，不是当前验证集最弱类别。不能根据训练集像素比例直接预判最终最差类别，也不能把验证类别排序当作测试类别排序。

测试0.669362证明有独立官方结果可作A00基线，但没有其他参赛者分数和排名，不应主观宣称“已很强”或“排名靠前”。

### 5.2 13.01个百分点差距的解释边界

可能原因包括：

1. 测试域场景、亮度、纹理、飞行高度或类别组合不同。
2. 随机patch划分未隔离同场景/相邻patch，验证可能更接近训练分布。
3. 训练权重利用了验证标签的汇总统计，评估隔离不够严格。
4. 每轮根据同一验证集选择best，单次验证峰值存在选择偏差。
5. 需要核对官方是否按全数据混淆矩阵聚合、Ignore和缺失类别如何处理；当前只有总分，没有官方评测实现可逐项对照。

这些是待检验假设，不是已证实原因。不能给每项分配“造成了多少个百分点”，也不能仅凭测试预测面积就定位混淆对象。

### 5.3 下一轮应该如何改进（建议，尚未实现）

建议按下列顺序，保持一次只验证一个主要因素：

1. **补证据**：备份云端split/profile/weights、Git SHA、依赖版本、官方提交回执；为验证增加混淆矩阵和错误样例导出。第一步先定位问题，不立即改模型。
2. **训练子集权重实验**：固定原split，仅将类别权重改为从6296张train标签计算，对照A00，修正验证统计参与训练超参数的问题。
3. **验证独立性审计**：检查重复/近重复、原始来源和场景分组。如改变split，先在新split上重跑原A00配置建立新基线；不能把换了验证集后的分数变化当作网络效果变化。
4. **外观鲁棒性实验**：在确认外观差异和验证错误后，单独加入适度gamma/阴影或扩大亮度范围，观察是否改善更独立验证集；不同时加大batch/epoch。
5. **裸地采样实验**：单独测试含裸地图像采样或按目标类别选择crop，避免当前5/7/8合并阈值经常被其他类别满足。增加采样可能造成背景误报，需要逐类precision/recall与混淆矩阵，而不仅看总mIoU。
6. **结构消融**：固定训练数据、种子、预算和增强，分别测试去掉边界辅助loss、去掉门控等明确假设。没有消融前不把A00成绩归因于边界模块。
7. **上下文实验**：单独测试crop640→768或更大；同batch下比较以减少混杂。更大crop可能保留更多上下文，也增加计算量，是否有效需实测。
8. **吞吐优化另记**：batch16等是速度候选而非已推荐的精度提升；需测每秒样本和GPU利用率，并意识到有效batch和优化步数变化。60→80/100轮也应独立实验，目前不是最高优先级。

不要用人工猜测的测试标签训练，不做测试集伪标签自训练，不用多模型或权重/预测平均。后续仍遵守单模型与官方数据约束。
